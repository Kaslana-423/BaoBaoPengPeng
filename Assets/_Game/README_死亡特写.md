# 死亡特写、旋转飞出与延迟复活

直接运行现有战斗场景。`RespawnController` 会自动接入死亡表现，无需重新搭建场景。

## 播放顺序

1. 致死碰撞记录受击方向，角色退出物理碰撞，隐藏自身血量/攻击力 UI。
2. 结束碰撞短时停与震屏，暂时冻结战场运动，保存镜头原位置和缩放。
3. 镜头在约 **0.18 秒**内移向死亡位置，缩放到原视野的 **55%**。
4. 角色身体及眼睛沿受击方向飞出，约 **0.42 秒**内旋转 **900°**，全程保持原大小，完全飞出屏幕后隐藏。飞行距离根据镜头视野和角色尺寸自动延长。只动画视觉子物体，不移动物理根节点或改写出生点。
5. 镜头用 **0.65 秒**缓缓回到原位置和原缩放，然后存活角色继续本次运动。死亡角色保持隐藏、无碰撞，**此时不会复活**。
6. 本次行动所有存活角色停稳后，结束伤害判定、隐藏总伤害 UI，进入 `RespawnWaiting`，统一等待 **0.8 秒**。
7. 优先在最初出生点满血复活；被敌方、友方或墙壁占用时，向周围寻找安全空位，预留间距，不穿过墙壁寻找场外落点。多人复活依次占用安全位置，彼此也不会重叠。原始出生点记录不变。
8. 复活完成后再弹出比分详情，然后换边；先到六分时先展示比分，再进入胜负结算。

其他小球在特写期间保留速度，不会因为特写丢失弹射动量。连杀或同一物理步内的多名角色死亡会排队播放特写，在本次行动结束后统一等待、复活，不会相互抢镜头。

死亡与复活不改变本大轮的使用情况：用过的角色仍用过，未用过的仍未用过。复活前已清空本次行动的攻击方，因此复活角色不会受到上一行动的伤害；下一次行动正常参与碰撞。墙角多次碰撞在死亡之前仍可连续扣血。

## 可调参数

选择 **`_Game/Resources/DeathPresentationSettings.asset`**：

| 参数 | 默认 | 用途 |
| --- | --- | --- |
| Enable Close Up | 开 | 是否移动并放大镜头；关闭后仍播放飞出与延迟复活 |
| Zoom Ratio | 0.55 | 相对原视野的比例，越小画面越近 |
| Zoom In Seconds | 0.18 | 拉近镜头的秒数 |
| Camera Return Seconds | 0.65 | 镜头缓缓恢复的秒数 |
| Fly Seconds | 0.42 | 旋转飞出的持续秒数 |
| Fly Distance | 4.5 | 最短飞行距离，运行时保证完全飞出屏幕 |
| Spin Degrees | 900 | 飞出过程中的总旋转角度 |
| Respawn Delay | 0.8 | 所有角色停止行动后等待的真实秒数 |
| Respawn Clearance | 0.08 | 复活时与其他角色和墙壁预留的世界距离 |

动画与复活等待均使用不受时间倍率影响的计时。等待期间冻结物理，锁定鼠标和 AI。极端情况下场地没有安全空位时保留待复活状态并输出警告，不强行重叠复活。

## 脚本与恢复处理

- `UnitActor.LastHitDirection`：记录最近一次实际受击方向。正常碰撞使用接触法线，并根据攻击方换算；没有接触点的伤害调用使用攻击者到受击者的方向。
- `TakeDamage(int, Vector2)`：可给其他伤害来源指定飞出方向；原有 `TakeDamage(int)` 接口保留，默认朝上。
- `UnitDeathVisual`：保存/恢复身体局部位置、旋转、缩放、激活状态和角色 Canvas 显隐。
- `DeathPresentationController`：镜头特写、飞出动画和暂停管理，镜头恢复后交还战场运动。
- `RespawnController`：死亡演出队列与待复活名单分开管理，`PendingCount` 包括本次行动全部尚未复活的角色；`IsPresenting` 只代表尚未完成的演出。
- `RespawnPlacement`：检查物理场景中的实际碰撞体，搜索出生点附近的安全空位。
- `PrototypeSession`：先结束运动和伤害，再调用延迟复活，最后交给比分与回合流程；重开前调用 `CancelPending()` 清理所有旧协程。

“再来一局”即使在飞出途中调用，也会停止旧动画、还原镜头和时间倍率、恢复所有角色的正常大小，再重置战斗。关闭/卸载战斗也会清理本系统持有的暂停和镜头状态。

编辑模式的既有回合/伤害规则验证继续使用两次 `ProcessPendingRespawns()` 的确定性接口；实际 Play 始终等待完整死亡表现和延迟，不会通过调用这个接口跳过动画。
